## ① 주제 확정 / Confirm topic

- **확정 주제 / Topic:** 막차연산알림 (술자리 귀가용 지하철 막차 기준 "일어날 시각" 역산 서비스, 이번 학기는 수도권 지하철에 집중)
- **이유 / Reason:** 지도앱은 "지금 출발하면" 기준의 경로만 보여줘서, 술집에서 역까지의 도보 시간, 환승, 중간 종착열차(예: 구파발행)를 반영한 **실제로 일어나야 할 시각**은 사용자가 직접 계산해야 한다. 술자리 분위기 때문에 계산을 미루다 막차를 놓치면 택시비 등 금전적 손해로 이어진다. 먼저 **한 사람이 출발역과 도착역만 넣으면** 몇 시에 역으로 출발해야 하는지와 집까지 걸리는 시간을 바로 알 수 있게 하고, 같은 술자리 친구들의 일어날 시각을 함께 보는 **팀 기능은 1인 기능이 완성되는 즉시 이어서 추가**한다.

### 핵심 사용 흐름 / Core user flow (Must, 1인 기준)

1. 메인화면 진입
2. **입력 화면:** 지금 술 마시고 있는 곳과 가장 가까운 지하철역(출발역), 집(또는 가야 할 곳)과 가장 가까운 지하철역(도착역)을 검색·선택하고, 요일 구분(평일/토요일/휴일, 오늘 날짜로 자동 선택·수정 가능)을 확인한다. 술집→출발역 도보 시간(기본 7분)과 여유 시간(기본 5분)은 필요하면 수정한다.
3. [계산하기] 선택
4. **결과 화면:**
   - **역으로 출발해야 할 시각(일어날 시각, HH:MM)**
   - **예상 소요 시간** (일어난 시각부터 도착역 도착까지: 도보 + 승차 + 환승)
   - 탑승할 열차 정보(출발 시각, 환승역)

> 출발역이나 도착역이 비어 있으면 [계산하기] 버튼이 비활성화된다.
> 팀 기능(팀명, 여러 명 입력, 일어날 시각 순 정렬)은 Must가 아니라 **Could의 첫 번째 항목**이며, Must 완료 직후 바로 착수한다. 여러 명의 정보를 어떤 방식으로 입력받을지(한 사람이 대신 입력 / 각자 팀에 입장)는 팀 기능 착수 전에 정한다.

## ③ 범위 결정 / Scope

### Must — 없으면 성립 안 됨 / essential

- **핵심 시나리오 / Core scenario:** 사용자 한 명이 메인화면에서 술자리 근처 지하철역(출발역)과 집 근처 지하철역(도착역)을 입력하고 [계산하기]를 누르면, 역으로 출발해야 할 시각(일어날 시각)과 집까지 예상 소요 시간, 탑승할 열차가 화면에 표시된다. 막차를 놓쳤거나 경로를 불러오지 못하면 시각 대신 안내 문구를 보여준다.
  - 해당 태스크: T1 ~ T11 전체
  - 실패 경로(T10)도 Must에 넣은 이유: 경로를 못 불러왔는데 엉뚱한 시각을 보여주면 그 시각을 믿고 막차를 놓치게 되므로, 틀린 시각보다 "모른다"고 알려주는 쪽이 서비스가 성립하는 조건이다.

### Should

- **시나리오 / 일어날 시각 임박 표시:** 결과 화면에서 일어날 시각까지 남은 시간이 카운트다운으로 표시되고, 10분 이내가 되면 강조된다. (푸시 알림 대신 화면 내 표시)
- **시나리오 / 막차 대안 경로 비교:** 막차 1개만이 아니라 막차 직전 열차 1~2개도 함께 보여줘, 조금 일찍 일어나면 환승이 덜한 경로를 고를 수 있다.

### Could

- **[Could 1순위] 시나리오 / 팀 기능:** 같은 술자리 친구들의 일어날 시각을 한 화면에서 함께 본다. **Must가 완료되면 가장 먼저 착수하는 핵심 Could**이며, 아래 순서로 붙인다.
  1. 팀명 입력 + 여러 명의 도착역 입력 (한 사람이 대신 입력할지, 각자 팀에 입장해 입력할지는 착수 전에 결정)
  2. 팀원의 일어날 시각을 빠른 순(오름차순)으로 정렬해 표시 (4주차 AC-3)
  3. 같은 열차를 타는 팀원끼리 묶어 "같이 나가면 되는 사람"으로 표시
  - 친구 정보가 들어가는 단계이므로, 3주차에서 짚은 대로 이름은 별명으로 받고 집 주소 대신 역 이름만 받는다.
- **시나리오 / 출발역 막차 실시간 확인:** 결과 상태가 `SOON`(일어날 시각 10분 전 이내)이나 `MISSED`일 때, 출발역에 오는 막차가 지금 어디쯤 있는지를 실시간 도착정보로 함께 보여준다. (예: "막차가 지금 2정거장 전, 약 4분 뒤 도착") 일어날 시각을 조금 넘겼어도 지금 뛰면 탈 수 있는지, 아니면 바로 다른 수단을 찾아야 하는지 판단할 수 있다. 일어날 시각 계산은 그대로 시간표 기준으로 하고 결과 화면에 정보만 덧붙이며, 환승역은 사용자가 할 수 있는 행동이 없어 출발역 막차 1개만 다룬다.
- **시나리오 / 현재 위치로 출발역 자동 추천:** 위치 권한을 허용하면 현재 위치에서 가장 가까운 지하철역을 출발역 후보로 먼저 보여준다.
- **시나리오 / 도보 시간 자동 계산:** 술집 이름이나 주소를 입력하면 출발역까지의 도보 시간을 지도 API로 계산해 기본값 7분 대신 채운다.
- **시나리오 / 막차 놓친 사람 대안 안내:** `MISSED`인 사용자에게 심야버스 등 대안 교통을 안내한다.

### 실행 가능성 확인 / Feasibility check

- **특수 장비·유료 API·실제 개인정보가 필요한가? 대안은?**
  - 특수 장비: 필요 없음. 노트북과 휴대폰 브라우저만 사용.
  - 유료 API: 경로·시간표는 ODsay 무료 키, 공휴일 판정은 한국천문연구원 특일 정보 API(무료)를 사용한다. 무료 호출량을 아끼기 위해 개발 중에는 같은 역 조합의 응답을 저장해 재사용하고, 시연용 경로의 응답도 미리 저장해 둔다.
  - 실제 개인정보: Must는 1인 기능이라 **사용자 본인의 출발역·도착역 이름만** 입력받고 서버에 저장하지 않는다. 집 주소나 현재 위치는 받지 않는다. 친구 정보는 Could의 팀 기능에서만 다루며, 그때 별명과 역 이름만 받고 팀 데이터는 당일 삭제한다.
- **15주차에 발표장에서 시연할 수 있는 형태인가?**
  - 가능. 웹 앱을 노트북이나 휴대폰 브라우저에서 실행해 시연한다.
  - 발표 시간(낮)에는 막차까지 시간이 많이 남아 결과가 와닿지 않으므로, **현재 시각을 직접 지정하는 시연 모드**(예: 23:30)를 둔다. AC-4 테스트(현재 시각 23:55 입력)에도 같은 기능을 쓴다.
  - 발표장 네트워크나 API가 불안정할 경우를 대비해 저장해 둔 응답으로도 같은 흐름을 보여줄 수 있게 하고, API 실패 경로(AC-5)도 함께 시연한다.
